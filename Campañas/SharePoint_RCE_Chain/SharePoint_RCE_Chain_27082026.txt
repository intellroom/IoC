RESUMEN
--------------------------------------------------------------------------------
Cadena publica que lleva de "sin credenciales" a ejecucion de codigo en
Microsoft SharePoint Server ON-PREMISE. Las dos mitades tienen PoC publicado.

  CVE-2026-55040  CVSS 9.1  Bypass de autenticacion por forja de token JWT
                            Componente: SPJsonWebSecurityTokenHandlerV2
                            CWE-1390 (Weak Authentication)
                            CISA KEV: 18-08-2026 (plazo 21-08-2026)

  CVE-2026-63520  CVSS 8.1  Instanciacion insegura de tipos .NET en
                            Business Data Connectivity (BCS/BDC)
                            Metodo: DbTypeReflector.ResolveDotNetType()
                            -> Type.GetType() sobre TypeName controlado

Origen: Pwn2Own Berlin 2026.

*** SHAREPOINT ONLINE / MICROSOFT 365 NO ESTA AFECTADO. Solo on-premise. ***

1. LO QUE **NO** ES UN IOC  (leer antes que las tablas)
--------------------------------------------------------------------------------

  "blahlist"  y  "blah.bdcm"   ->  NO SON INDICADORES DE COMPROMISO

Son las cadenas literales que usa el PoC de VulnCheck en su demostracion.
El atacante las cambia escribiendo dos palabras. Una regla construida sobre
esos strings da sensacion de cobertura y no cubre nada.

  /_api/web/lists
  /_vti_bin/client.svc/ProcessQuery
  /_api/web/GetFolderByServerRelativeUrl(...)

Son API LEGITIMA y de alto uso de SharePoint. Bloquearlas rompe el producto.
La deteccion tiene que ser por SECUENCIA y por CONTENIDO, no por endpoint.

3. ARTEFACTOS DE ALTA FIDELIDAD  (esto es lo que si sirve)
--------------------------------------------------------------------------------

[A-01] Biblioteca de documentos "BusinessDataMetadataCatalog" (template type 101)
       creada por via API en un sitio que no usa BCS.
       Fidelidad: ALTA - anomala por si sola.

[A-02] Archivo con extension .bdcm subido a esa biblioteca.
       Fidelidad: ALTA - un modelo BDC casi nunca se sube por API REST.

[A-03] Registro de lista externa con tipo "DotNetAssembly" via ProcessQuery.
       Fidelidad: ALTA - combinacion especifica de la explotacion.

[A-04] PROCESO HIJO DE w3wp.exe  (cmd.exe, powershell.exe, calc.exe, cualquiera)
       Fidelidad: MUY ALTA - el application pool de SharePoint no debe generar
       procesos hijo interactivos. ES LA SEÑAL MAS FUERTE DE LA CADENA.

[A-05] Referencias dentro de un modelo BDC a:
         System.Web.UI.LosFormatter
         TypeConfuseDelegate
         ObjectDataProvider
       Fidelidad: ALTA.
       *** Existen MULTIPLES cadenas de gadgets. VulnCheck documento
           LosFormatter/TypeConfuseDelegate; Rapid7 documento ObjectDataProvider.
           Una deteccion que busque solo una FALLA contra la otra. ***

[A-06] Payload base64 embebido en el campo "DefaultValue" de un BDCM.
       Fidelidad: ALTA.

[A-07] Enumeracion masiva de administradores tras acceso sin autenticacion
       previa exitosa. Fidelidad: MEDIA - patron observado el 25-08-2026.

[A-08] Consultas SMB / LSARPC de descubrimiento de SID contra el DC desde
       origen externo. Fidelidad: MEDIA - el PoC lo usa para resolver
       identidades (necesita SID o UPN valido del objetivo).

4. SECUENCIA DE EXPLOTACION
--------------------------------------------------------------------------------

 0. (JWT forjado)                                    -> bypass CVE-2026-55040
 1. POST /_api/web/lists   |   POST /_api/web/folders
                             -> crea BusinessDataMetadataCatalog (tipo 101)
 2. POST /_api/web/GetFolderByServerRelativeUrl('BusinessDataMetadataCatalog')/Files/add
                             -> sube el modelo .bdcm malicioso
 3. POST /_vti_bin/client.svc/ProcessQuery
                             -> registra lista externa (tipo DotNetAssembly)
 4. GET  /_api/web/lists/getbytitle('<lista>')/items
                             -> dispara ejecucion via Finder (FindSpecificDefault)

 Resultado: proceso hijo bajo w3wp.exe.

 NOTA: VulnCheck describe el paso 1 contra /_api/web/lists y Rapid7 contra
 /_api/web/folders. Cubrir AMBAS rutas, no elegir una.

        (la mas valiosa: no depende de strings del PoC, sobrevive al renombre)

title: Proceso hijo sospechoso desde el app pool de SharePoint (w3wp.exe)
id: 4f2a8b91-6c37-4e50-9d18-2a5f7c3e1b64
status: experimental
author: Intellroom CTI (AI-assisted - VALIDAR ANTES DE DESPLEGAR)

[KQL] Microsoft Sentinel / Defender XDR - ejecucion desde el app pool

DeviceProcessEvents
| where InitiatingProcessFileName =~ "w3wp.exe"
| where FileName in~ ("cmd.exe","powershell.exe","pwsh.exe","cscript.exe",
                     "wscript.exe","mshta.exe","rundll32.exe","regsvr32.exe",
                     "certutil.exe","bitsadmin.exe","curl.exe","calc.exe")
| project Timestamp, DeviceName, AccountName, FileName, ProcessCommandLine,
          InitiatingProcessCommandLine, ReportId
| order by Timestamp desc


[KQL] Secuencia de la cadena en logs de IIS (ventana de 30 min por IP)
      La secuencia es lo que discrimina; los endpoints sueltos son trafico normal.

let ventana = 30m;
let paso_catalogo = W3CIISLog
  | where csMethod == "POST"
  | where csUriStem has_any ("/_api/web/lists", "/_api/web/folders")
  | project Tiempo=TimeGenerated, IP=cIP, Paso="1-crear-catalogo";
let paso_bdcm = W3CIISLog
  | where csMethod == "POST"
  | where csUriStem has "BusinessDataMetadataCatalog"
  | project Tiempo=TimeGenerated, IP=cIP, Paso="2-subir-bdcm";
let paso_processquery = W3CIISLog
  | where csMethod == "POST"
  | where csUriStem has "/_vti_bin/client.svc/ProcessQuery"
  | project Tiempo=TimeGenerated, IP=cIP, Paso="3-registrar-lista";
union paso_catalogo, paso_bdcm, paso_processquery
| summarize Pasos=make_set(Paso), Primero=min(Tiempo), Ultimo=max(Tiempo)
          by IP, bin(Tiempo, ventana)
| where array_length(Pasos) >= 2 and set_has_element(Pasos, "2-subir-bdcm")
| order by Primero desc


[SPL] Splunk - proceso hijo desde w3wp.exe

index=windows sourcetype=WinEventLog:Sysmon EventCode=1
  parent_process_name="w3wp.exe"
  process_name IN ("cmd.exe","powershell.exe","pwsh.exe","cscript.exe",
                   "wscript.exe","mshta.exe","rundll32.exe","regsvr32.exe",
                   "certutil.exe","bitsadmin.exe","curl.exe","calc.exe")
| table _time host user parent_process_name process_name process
| sort - _time


[SPL] Splunk - secuencia en IIS

index=iis (cs_method=POST)
  (cs_uri_stem="*BusinessDataMetadataCatalog*" OR cs_uri_stem="*client.svc/ProcessQuery*")
| stats values(cs_uri_stem) as endpoints dc(cs_uri_stem) as n_endpoints
         min(_time) as primero max(_time) as ultimo by c_ip
| where n_endpoints >= 2
| convert ctime(primero) ctime(ultimo)

6. CAZA RETROACTIVA
--------------------------------------------------------------------------------

VENTANA A BARRER: desde el 11-08-2026 (primer PoC publico).
Si la organizacion parcho despues del 12-08-2026, la caza NO es opcional:
el parche no expulsa a quien ya entro.

 H-1  Biblioteca BusinessDataMetadataCatalog creada en sitio que no usa BCS
      -> inventario de bibliotecas por sitio (template 101) + fecha de creacion
 H-2  Archivo .bdcm subido por API en el periodo
      -> contenido de la biblioteca + Created By + Created
 H-3  w3wp.exe genero procesos hijo desde el 11-08-2026
      -> EDR / Sysmon EventID 1        *** CONFIRMA RCE EFECTIVA ***
 H-4  Autenticaciones exitosas sin evento previo de autenticacion valida
      -> logs IIS + ULS de SharePoint (bypass JWT ejercido)
 H-5  Enumeracion masiva de administradores desde origen externo
      -> logs IIS (patron observado por Defused el 25-08-2026)
 H-6  Lista externa registrada con tipo DotNetAssembly
      -> configuracion de BCS

 SI H-3 DA POSITIVO: deja de ser gestion de vulnerabilidades y pasa a
 respuesta a incidentes. NO cerrar el ticket parchando.

9. EXPOSICION - LO MEDIDO Y LO QUE NO SE PUEDE AFIRMAR
--------------------------------------------------------------------------------

MEDIDO:
  Shadowserver rastrea mas de 8.700 servidores SharePoint expuestos a internet
  (cifra GLOBAL, agosto 2026, via BleepingComputer). No distingue version
  parchada de vulnerable ni desglosa por pais.

  CISA tiene nueve vulnerabilidades de SharePoint en KEV, tres asociadas a
  ToolShell. SharePoint on-premise es superficie recurrente, no un caso aislado.

NO SE PUEDE AFIRMAR:
  No existe, en las fuentes consultadas, cifra verificable de servidores
  SharePoint on-premise vulnerables por pais en LATAM.

  Se descarto una afirmacion de "miles de instancias vulnerables en Mexico,
  Colombia, Chile y Argentina" porque provenia de una fuente secundaria que en
  el mismo articulo atribuye la campana a CVE-2026-20963, identificador que NO
  corresponde a esta cadena.

  Para obtener el dato real: dashboard publico de Shadowserver filtrado por
  pais, o consulta Shodan/Censys correlacionada contra el build (un banner NO
  prueba version vulnerable).
