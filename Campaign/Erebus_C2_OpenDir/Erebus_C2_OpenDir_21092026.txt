RESUMEN
--------------------------------------------------------------------------------
Un investigador independiente (Yusuf Can Cakir, @Yusufcancakiir) publico en X,
el 21-09-2026 a las 19:10 UTC, el hallazgo de un servidor expuesto que aloja
lo que describe como un C2 propio llamado "Erebus": un servidor en Python, un
implante de Windows en Rust, un agente PowerShell mas antiguo, payloads,
.bash_history, rastros de desarrollo y codigo de exfiltracion por Telegram.
Advierte que el agente PowerShell y la version nueva (Rust +
Python) no usan el mismo protocolo, y lo lee como etapas distintas del
desarrollo: la nueva se comunica por TCP/8080 con JSON con prefijo de largo y
una capa XOR simple. No lo conecta con ningun actor conocido y lo presenta como
un hallazgo menor.

Intellroom lo contrasto de forma PASIVA con datos que el autor del post no
controla: los banners de Shodan de la misma direccion (consulta por API, sin
tocar el servidor). Confirman lo esencial:

  1. El servidor existe y estaba expuesto: HTTP en el puerto 80 con banner
     SimpleHTTP/0.6 Python/3.14.4 (python -m http.server) y titulo "Directory
     listing for /", en una instancia EC2 de AWS Sao Paulo (sa-east-1, AS16509).
  2. El listado de la raiz (14 entradas al 21-09) contiene tres de los
     artefactos que nombra el post -- usermode_font_driver.exe, payload.bin y
     .bash_history -- mas c2_modules/, transfer/, BACKUP/, .ssh/ y dos logs de
     servidores HTTP (http-server-80.log y http-server-8080.log).
  3. La exposicion observada abarca al menos 5 dias y 19 horas: el directorio
     abierto aparece por primera vez el 15-09-2026 a las 20:47 UTC y sigue en el
     banner del 21-09-2026 a las 15:40 UTC.
  4. El material se sigue tocando: entre el 15-09 y el 21-09 se agregaron
     usermode_font_driver.exe y BACKUP/. Lo ve Shodan, sin depender del post, y
     es coherente con la lectura del investigador (un C2 en distintas etapas).

Lo que NO se sabe (seccion 9): quien lo opera ni con que fin (criminal, ejercicio
ofensivo autorizado o laboratorio de desarrollo), si existe alguna victima, si el
servidor de control sigue activo, y que contienen realmente los archivos.
Intellroom no descargo, no abrio ni contacto el servidor.

Convencion: "operador" es quien maneja este material, sea o no el dueno del
servidor; no se sabe cual de las dos cosas es (seccion 9).

Confianza en que la direccion sirviera el 21-09 un directorio abierto con el
  material descrito (nombres de archivo): ALTA (post + banners de Shodan).
Confianza en que ese material sea un C2 en preparacion: MEDIA. Solo lo afirma el
  post; los nombres del listado (c2_modules/, payload.bin) son consistentes.
Confianza en la descripcion tecnica (Rust, XOR, Telegram): BAJA. Depende de una
  sola persona y nadie mas vio el contenido.
Confianza en que sea una amenaza activa contra victimas reales: BAJA. Ninguna

Confianza en la atribucion a un actor o campana: NULA.

1. LO QUE NO ES UN IOC  (leer antes que las tablas)
--------------------------------------------------------------------------------

  api.telegram.org  ->  SERVICIO LEGITIMO ABUSADO: NO SE BLOQUEA EN BLOQUE

  Es el punto de enlace de la API de bots de Telegram y lo usan millones de
  aplicaciones legitimas. Que el codigo del operador lo use para exfiltrar no
  lo convierte en infraestructura maliciosa. Bloquearlo en toda una
  organizacion es una decision de politica, no un hallazgo de esta ficha. Se
  detecta por COMPORTAMIENTO (seccion 7).

  AS16509 y el bloque /16 de AMAZON-GRU  ->  NUNCA SE BLOQUEAN

  Son de Amazon y contienen miles de clientes legitimos. Solo la direccion
  puntual de la seccion 3 se bloquea, y con fecha de revision.

  "Erebus"  ->  NOMBRE HOMONIMO, NO ES UNA FIRMA

  El nombre lo usa tambien un framework de comando y control para ejercicios
  ofensivos autorizados, publicado en GitHub (repositorio KKingZero/ARK; la
  direccion KKingZero/Erebus redirige a el). Se leyo su README: su servidor es
  Go, su implante principal esta en C y habla protobuf sobre HTTPS o DNS con
  AES-256-GCM. No coincide con
  lo que describe el post (servidor Python, implante Rust, TCP/8080 con JSON +
  XOR). No hay evidencia de relacion. NO usar el nombre para atribuir ni para
  escribir reglas.

  .bash_history, .bashrc, .profile, .bash_logout, .ssh/, .cache/, .local/  ->
  ARCHIVOS DEL HOME DEL SERVIDOR EXPUESTO, NO FIRMAS

  Es el directorio de usuario Linux del servidor expuesto, servido por
  descuido. No van a aparecer en el equipo de ninguna victima.

  c2_modules/, transfer/, BACKUP/, http-server-80.log, http-server-8080.log  ->
  NOMBRES EN EL SERVIDOR EXPUESTO, NO FIRMAS

  Describen como trabaja el operador, no que dejaria en una victima. Sirven para
  entender el caso, no para escribir una regla.

  "SimpleHTTP/0.6 Python/3.14.4" y "Directory listing for /"  ->  NO ES UN IOC

  Es el banner del servidor de archivos que trae Python (python -m http.server).
  Lo usan millones de servidores de desarrollo legitimos. Sirve para encontrar
  directorios abiertos, no para acusar a un servidor concreto.

  Puertos 80 y 8080  ->  NO SON FIRMA POR SI SOLOS

  Son puertos de uso corriente para HTTP. Lo llamativo es trafico que NO sea HTTP
  en el 8080 hacia la direccion de la seccion 3, no el puerto en si.

  fontdrvhost.exe ("Usermode Font Driver Host")  ->  ES EL PROCESO LEGITIMO

  El nombre usermode_font_driver.exe recuerda al componente legitimo de Windows
  fontdrvhost.exe, que vive en System32 y esta firmado por Microsoft. No
  confundir ni bloquear el legitimo.

  Fragmentos del token de Telegram  ->  NO SE PUBLICAN

  El autor del post publico el token truncado. Intellroom no lo reconstruye, no
  lo usa y no lo reproduce: un token completo daria control del bot.

5. ANALISIS  (interpretacion de Intellroom, separada de lo verificado)
--------------------------------------------------------------------------------

5.1 Error operativo repetido. Quien opera el servidor dejo su directorio de
    trabajo servido con python -m http.server. Es el tercer caso de este
    investigador que Intellroom registra en 12 dias (09-09 Pfcloud, 14-09
    SurAsia, hoy). En los tres el servidor de archivos es el mismo
    (SimpleHTTP/0.6) y en este y en el de SurAsia la version de Python coincide
    (3.14.4), pero es una version reciente y comun: NO se establece relacion.
    Distinto proveedor, pais y herramientas.
5.2 Direccion de nube reasignable. La ultima vez que Shodan la vio como
    balanceador de otro cliente de AWS fue el 17-08, y puede volver a asignarse a
    un tercero cuando quien la usa libere la instancia. Un bloqueo que se olvida
    termina castigando a un tercero inocente: por eso el bloqueo lleva fecha de
    revision (seccion 8).
5.3 Desarrollo activo. usermode_font_driver.exe no estaba el 15-09 y si el 21-09.
    Junto con el post (dos etapas de desarrollo) sugiere que el implante de Rust
    es reciente. Para un defensor significa que las huellas de hoy pueden no
    servir manana: cada compilacion nueva cambia el SHA-256. Vale mas el
    comportamiento (seccion 7) que la huella.
5.4 Nombre del implante. usermode_font_driver.exe imita el vocabulario de
    fontdrvhost.exe ("Usermode Font Driver Host"), un proceso legitimo presente
    en todo Windows moderno. Es una inferencia por el nombre (confianza BAJA): el
    post no dice que sea un disfraz. Renombrar binarios como procesos de Windows
    es una tecnica comun y no es firma de ningun actor.
5.5 Senales debiles de contexto regional (NO son atribucion). La direccion esta
    en la region AWS de Sao Paulo y el agente PowerShell se llama "agente.ps1",
    palabra que existe en espanol y en portugues. Juntas no alcanzan para hablar
    de objetivo ni de origen; se dejan por si aparece un segundo dato. Confianza
    BAJA.
